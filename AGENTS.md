# AGENTS.md — Правила разработки и стандарты проекта

Этот файл определяет правила, соглашения по коду и архитектурные принципы для разработчиков и AI-ассистентов в репозитории **White-Label E-Commerce Platform**.

---

## 1. Общие принципы

1. **Дизайн в приоритете (Design-First):**
   * Все компоненты интерфейса строятся на основе дизайн-системы **Luminescent Commerce** (сгенерированной в Stitch).
   * Основные токены:
     * `primary`: `#006948` (глубокий изумрудный)
     * `secondary`: `#fea619` / `#f59e0b` (теплый янтарный для бейджей, скидок и рейтингов)
     * `surface`: `#faf8ff` (чистая нейтральная основа)
     * `text-main`: `#131b2e` (Slate-900)
     * Шрифты: **Plus Jakarta Sans** (заголовки, hero, баннеры), **Inter** (основной текст, таблицы, формы, метаданные).

2. **Модульность и чистая архитектура:**
   * Четкое разделение ответственности: `Frontend (UI/Components)` ↔ `API Service` ↔ `Database & Models`.
   * Избегать монолитных спагетти-файлов. Компоненты UI должны быть изолированными и переиспользуемыми.

3. **Локализация и i18n:**
   * Проект изначально двуязычный: русский (`ru`) и английский (`en`).
   * Строки интерфейса не захардкоживать напрямую в логику компонентов; использовать структуру словарей/i18n.

## 3. Правила написания кода

* **TypeScript / Modern JavaScript:** Строгая типизация моделей данных (`Product`, `OrderItem`, `User`, `CartState`).
* **Tailwind CSS:** Использовать классы утилит с настроенной темой из дизайн-системы, не писать разрозненный ad-hoc CSS.
* **Безопасность данных:**
  * Никаких API-ключей, токенов или секретов в открытом коде. Все конфиденциальные ключи выносить в `.env`.
  * Валидация входных данных на бэкенде перед записью в базу.
* **Git соглашения:**
  * Коммиты оформлять по Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `chore:`.
